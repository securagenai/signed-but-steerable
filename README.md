# Signed but Steerable: the text-vector integrity gap in offline RAG

Code, data and results for the paper *Signed but Steerable: Measuring and Closing the Text-Vector Integrity Gap
in Offline Retrieval-Augmented Generation* (G. Feretzakis, A. Papaspyridis, securagen.ai).
arXiv identifier and Zenodo DOI: to be added at release.

## What is here
- `ragtrust/` shared library, including `codeverify.py`, the reference code-level verifier used for every
  code-verification result (ambiguity decided only from the verifier's recomputation; neighbour-only
  acceptance; canonicalisation).
- `desktop/` experiments run on the desktop: abstention scoring (E1) and its MS MARCO check, the vector
  desynchronisation attack and the margin law (E7), BEIR margins, vector-database exposure, the FAISS
  demonstration, code-level verification and the determinism of float pipelines.
- `device/` experiments run on the Raspberry Pi 5 CPU: context pruning (E2), the cost of verification next to the
  language model (E4), device-side embedding and INT8 fidelity (E5), the end-to-end attack (E7) and pack updates (E8).
- `analysis/` analyses, the precision and unit checks, and `make_figures.py`, which regenerates the figures.
- `data/` the SQuAD-derived corpus, windows, questions and vectors; `results/` per-experiment outputs;
  `tests/` unit tests; `remote/` helpers to drive the Pi from the desktop (adapt host names).
- `PROTOCOL.md` hypotheses fixed before data collection and the log of deviations and exploratory analyses.
  Experiment numbers follow the protocol; E3 and E6 are not part of this release.
- `pins.json` pinned revisions of models and tools.

## Quick start
- Tests: `python tests/test_codeverify.py`.
- Desktop environment: `bash desktop/setup_desktop.sh`; figures: `python analysis/make_figures.py`.
- Device experiments: a Raspberry Pi 5, Python with `device/requirements_device.txt`, and llama.cpp at the commit in `pins.json`.

## Running the device experiments
On the Raspberry Pi, after `cp device/config.env.example device/config.env` (adapt the paths) and installing
`device/requirements_device.txt` into `venv_device`:
- E2 and E7 generation: `bash device/inner_generate.sh` (starts llama-server and runs every configuration whose
  contexts exist); the CPU-INT8 end-to-end configuration alone: `bash device/run_e7_cpu_int8.sh`.
- E4: `python device/e4_contention.py`; E5: `python device/e5_reindex.py --backends ort-fp32,ort-int8`;
  E8: `python device/e8_device_verify.py --vector-backend ort-fp32`.
- From the desktop, `remote/pi_sync.sh` copies the repository to the Pi and `remote/pi_fetch.sh` fetches results.

## Not included
- Model weights and exported ONNX graphs (licences): downloaded and rebuilt by the scripts at the pinned revisions.
- BEIR and MS MARCO data and derived vectors (licences): downloaded by the scripts.
- Large vector files and caches, regenerated by the scripts: `results/e7/squad_question_vectors.npz`
  (`analysis/margin_law_squad.py`) and `results/e7/proxy_vectors.npz` (`analysis/margin_law.py`).
- Intermediate inputs regenerated or downloaded by the scripts: `results/e7/vecs/` (written by
  `desktop/beir_margins.py`), `results/e7/scale_*.npy` (written by the code-verification scripts),
  `data/beir/` and `artifacts/models/` (written by `desktop/export_onnx.py`).
- Run logs.

Some analysis scripts load caches that they created themselves with `numpy.load(..., allow_pickle=True)`;
load such files only from your own runs, never from untrusted sources.
